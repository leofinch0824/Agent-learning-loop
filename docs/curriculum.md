# Agent 核心思想、运行机制与业务实践

更新：2026-09-13。本文是唯一课程总纲：学习目标、必修内容、排期和掌握标准在此维护；目录与实验实现见 [DESIGN.md](DESIGN.md)。

## 1. 学习目标与边界

课程首先培养可迁移的 Agent 设计和实现能力：能够判断是否需要 Agent，解释模型决策与程序控制的分工，构建工具—环境反馈循环，处理上下文、记忆、规划、协作、恢复和权限，并用评测决定系统是否值得改进。LangGraph 是验证机制的主要载体；业务项目用于练习和验收这些能力。

学习者为算法工程师，已有 Python 和大模型算法原理基础，接受付费 API。工作日至少每天 1 小时、周末每天 4–5 小时，按每周 13–15 小时、8 周约 104–120 小时安排。Python/模型原理按缺口补充；Agent 思想与机制依据迁移练习决定是否跳过，不依据职业背景默认掌握。API 预算和模型在实际实验时明确。

贯穿项目为“PCB 制造工艺参数抽取与迭代助手”：从制造工艺设计文档（PDF、Word）抽取工艺参数，沉淀业务知识，以可定制和可优化 Skill 支持错例分析、提示词改进及需要人工核验的 SFT/偏好/RL 任务素材挖掘。

学习者已确认：当前流程主要是文档转图片，再交给多模态模型识别、推断并抽取参数；已有 100 条以上样本。模型名称由学习者描述为“Qwen3.8”等，具体服务和模型 ID 在接入时核对。样本计数单位、人工标注完整度和证据定位情况尚未核验，不能把“100 条以上样本”等同于“100 份已标注文档”。现有流程作为待复现基线，数据无需从零构造。

**通用部分的基本思想和最小实验均为必修，不因贯穿项目暂时用不到而取消。** 时间不足时减少业务样本、优化轮数、算法对照和界面开发；不能用“接进项目就算学过”代替独立机制实验。

## 2. 通用主干：L0–L7

每课依次完成“思想与取舍 → 最小机制实验 → 反例/修复 → 迁移”。下表时间是初始教学估算，含阅读、实验和复盘。

| 单元                          | 必修思想与机制                                                                                                                        | 最小实验和掌握证据                                                                                                                          | 预算 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| L0 为什么需要 Agent           | 单次模型调用、固定 Workflow、Agent 的区别；目标/行动/观察/反馈；模型、工具、runtime/harness 的分工；自主性、质量、延迟与成本取舍      | 对同一小任务设计脚本、固定工作流、模型自主循环三种方案；执行可比较的最小基线；能指出哪种场景不应增加 Agent 复杂度                           | 4 h  |
| L1 状态与执行模型             | State/Node/Edge；channel/reducer；super-step；并发快照；普通多入边与显式汇聚；输入输出与私有状态                                      | 复用现有课件；并发写冲突；非对称路径直接统计汇聚调用次数；检查流式输出范围；换拓扑仍能预测和解释                                            | 6 h  |
| L2 决策、工具循环与终止       | 原生 Python 循环与图循环；ReAct 式行动—观察；结构化工具调用；条件边、Command；流式事件；成功/失败/无进展/预算终止                     | fake 保证调度可验证，真实模型验证工具闭环；坏参数回传；重复调用；静态边与动态路由并存反例；从 trace 解释停止原因                            | 8 h  |
| L3 工具系统与执行边界         | 工具 schema/语义/结果契约；只读与写入；并发冲突；超时、重试、取消；模型建议与权限执行分离；沙箱隔离；MCP 的协议边界                   | 相同工具直接调用与本地 MCP 调用对照；两个读任务并行、冲突写受控；未授权动作在执行层被拒绝；用实际配置的隔离环境验证越界访问失败；故障可追踪 | 8 h  |
| L4 持久化、人机协作与可靠执行 | checkpoint 与 thread；memory/SQLite；durability 的 exit/async/sync；历史查询、分叉；动态 interrupt 与静态断点；恢复重放、幂等         | 分别在写操作前后注入进程退出；重启恢复；接受/修改/拒绝审核；多个中断顺序对照；记录重执行范围；说明外部撤销与历史分叉的区别                  | 10 h |
| L5 上下文、检索与记忆         | 工作上下文、会话状态、checkpoint、跨会话 Store 的分工；检索与写回；记忆更新/冲突/过期；裁剪/摘要/选择性加载；缓存前缀与真实命中区分   | 新 thread 读取经确认记忆；错误记忆纠正/失效；噪声上下文对照；裁剪和摘要后检查关键信息；长工具结果管理；做缓存遥测或明确标记未实测           | 10 h |
| L6 规划、子图与多 Agent       | 固定分解、Plan-and-Execute、重规划；Send/map-reduce；共享/独立 state；状态翻译、Command.PARENT、checkpoint 命名空间；委派与上下文隔离 | 同一任务对比单 Agent、固定流程、planner+两个 worker；子图状态检查；任务失败后的重规划；汇聚与冲突处理；能解释协作何时无收益                 | 10 h |
| L7 可观测、评测与反馈改进     | run/trace/span；结果评价与轨迹评价；数据分组和留出；失败归因；规则评价/人工评价/LLM judge；资源预算；反思与 evaluator-optimizer       | 复用 MLflow 定位失败和成本；提前已有的基线在此扩展；校准 judge；故意“高分但任务失败”的反例；一次简单反思前后对照；报告未知和退化            | 10 h |

基础主干约 66 小时。L0 的概念也贯穿所有课；从 L2 起有原始 trace、小型结果集与费用记录，L7 系统化整合，不能等到 L7 才开始验证。

依赖以问题为准：L1 支撑 L2/L6 的调度理解；L2 支撑 L3 的工具治理；checkpoint 先于恢复和 interrupt；L5 的上下文分工先于 L6 的隔离比较；可靠评价先于业务自优化。L3 先验证执行层拒绝，L4 再加入持久化审批。

## 3. 业务迁移：L8–L10

每个业务单元继续明确它复用了哪些通用能力，保留成功、拒绝和失败路径。

| 单元                      | 通用能力迁移与业务增量                                                                                                  | 交付与掌握证据                                                                                                                               | 预算 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| L8 业务知识、Skill 与流程 | 将知识/记忆、工具契约、子图和版本管理组合；Skill 的加载、定制、说明、示例、工具使用及结果约束；业务规则有来源和适用范围 | 两个 Skill 共用规则；同一 Skill 被两条流程调用；规则更新不改变已运行任务的版本；人工拒绝候选知识；从知识加载到输出实际生效                   | 8 h  |
| L9 多模态归因与自动优化   | 把 L7 评测/反思用于图文业务；证据页/区域、预处理、标签歧义；提示词优化与 Skill 自迭代；搜索、验证、晋升和回退           | 对照给定正确证据与实际选证据；归因假设用小型干预核验；固定基线/一轮反思/一种现成优化器（首选 GEPA）比较；只改声明的 Skill 组件；候选可被拒绝 | 12 h |
| L10 数据挖掘与综合验收    | 将恢复、审核、评测和反馈用到离线导出的线上记录/模型结果；分流为修输入、修规则、优化、核验或训练数据候选                 | 同源去重、多样性筛选、人工纠正；分别导出 SFT、偏好和 RL 任务素材；加载校验；同等审核额度下对照随机抽样；完成业务闭环和跨业务迁移题           | 12 h |

业务主线约 32 小时；加上通用主干共 98 小时，8 周剩余约 6–22 小时作为数据准备超支、故障处理和复习缓冲。估算不包含大规模标注或训练集群搭建。

业务实现可从 L2 起逐渐积累，正式知识/Skill 和优化集中在后段。已有算法经验用于减少优化算法入门和代码编写时间，而不省略评价和人工判定。

| 周  | 建议内容             | 阶段验收                                                                              |

| W5  | 完成 L6、L7          | 规划/多 Agent 对照、独立评测与基础反思闭环；通用主干验收                              |

| W7  | L9                   | 多模态错例分析；一次有预算、有验证的 prompt/Skill 候选迭代                            |

工作日一小时可按“10 分钟回忆/预测、35 分钟实验、15 分钟解释记录”推进；周末做较长运行与人工审核。学习记录放在各课 README 的完成记录或项目实验报告，不再新增一套全局学习日志文档。AI 可生成骨架、解释源码和提出反例；每课至少一个关键预测和迁移修改由学习者先独立尝试。

## 6. 验收与当前进度

课程完成需同时检查四项：实现存在、机制实验通过、真实模型/环境验证、学习者独立迁移。未运行的 live、缓存或隔离实验明确写“未验证”，不能用 fake 或 skip 充当通过。

通用主干验收：解释 Agent/Workflow 选择；从 trace 还原行动和状态；修复一个并发、记忆或重放反例；比较单 Agent 与多 Agent；说明 runtime 如何约束行动；建立不依赖自我宣称的成功判据。

业务验收：运行“评估—归因—优化—审核”和“筛选—纠正—导出”；提供一次接受或拒绝优化候选的证据；审核中重启可恢复；数据素材有来源、版本和人工判定。只导出数据时不宣称后训练收益；有已有训练脚本/算力时，可替换部分优化广度做真实训练前后对比。

跨业务迁移题：换成与主项目不同的小任务（例如资料检索或代码检查），由学习者独立选 workflow/agent、定义工具与状态、设置退出条件、做一次故障恢复和小型评价。允许复用通用代码，但须说明哪些业务假设不能迁移。

当前仅 L1 有课件，且部分概念和断言待校正；L0、L2–L10 为规划。本轮只调整文档，没有新增课程代码或宣称真实验收完成。
