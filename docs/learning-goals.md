# 已确认的学习目标与成果范围

更新：2026-09-13。依据学习者本轮明确反馈；具体首个业务案例仍可调整。

## 学习者与投入

- 算法工程师，已有大模型算法原理和 Python 开发基础，不安排通用 Python 或大模型原理入门。
- 工作日至少每天 1 小时，周末每天约 4–5 小时，按每周 13–15 小时排期。
- 目标周期为 1–2 个月：4 周约 52–60 小时，8 周约 104–120 小时。课件采用 AI 辅助实现与解释，理解和验收仍需要学习者参与。
- 接受付费 API 调用。提供商、具体模型及单次实验预算在实际接入时配置；“可付费”不等于预算无限。
- pytest、LangGraph 和工具调用熟悉程度尚未确认，用短诊断练习决定是否跳过基础，不推定已掌握。

## 已确认的目标

构建能够沉淀业务逻辑、使用可定制且可自动优化 Skill 的 Agent，支持业务流程构建。重点实践多模态模型提示词优化、模型错题分析与归因，以及从线上数据或模型结果挖掘后训练数据；这些流程应能容纳大量人工核验。

## 建议的贯穿项目

**业务模型迭代助手**：接收业务资料、输入样本和模型结果，依据业务知识与 Skill 组织评估和错例分析；将问题分流为提示词/Skill 改进、输入或工具修复、业务知识核验、训练数据候选；经人工审阅和独立评测后形成可追溯成果。

首个任务暂以“多模态文档/图表理解与结构化信息抽取”为可替换教学占位，并非用户已选择的业务。数据缺失时先使用小型公开或自制样例，不自动读取其他工作项目或线上系统。

## 两档交付范围

| 时间 | 目标成果 | 验收边界 |
| --- | --- | --- |
| 4 周 | 一条完整的最小路径：固定版本业务 Skill → 真实多模态推理 → 评测 → 少量错例人工核验 → 一轮自动提示词候选与对照 → 接受或拒绝候选 | 能解释一次收益或失败；不要求通用 Skill 优化器、全面数据挖掘和部署 |
| 8 周 | 在同一个业务上补齐可恢复审核、业务流程组合、Skill 版本迭代、数据筛选与 SFT/偏好/RL 任务素材导出，完成一次完整复盘 | 有真实输入、人工确认、独立评测与版本证据；这是可用原型及算法工作流，生产规模另行验收 |

8 周计划将实际 SFT/RL 训练作业接入列为可选扩展，主线完成数据侧与评测侧接口。若已有可用训练环境和稳定训练脚本，可缩减优化算法对照的广度，换取一次真实训练前后对比。只完成数据导出时，结论限于数据工作流完成，不能宣称模型能力提升。

## 期望学习成果

1. **组织业务知识与 Skill**：独立新增一个 Skill，引用业务规则及案例，处理规则更新和冲突，不靠把所有历史塞入提示词。
2. **构建业务流程**：组合“评测—分析—优化”和“挖掘—审核—导出”两条流程，暂停后恢复，正确处理拒绝和审核修改。
3. **多模态评估与归因**：保留原始视觉证据，区分信息未提供、视觉理解错误、规则不清、标注错误与可被提示词改进的问题；允许归因未知。
4. **自动优化**：能运行有预算的候选搜索，对比固定基线、一轮反思和一种现成优化器；报告跨样本收益、回退及停止理由。
5. **训练数据挖掘**：能从模型输出中挑出值得人工审阅的案例，记录选择理由；区分 SFT 修正答案、偏好关系与可验证 RL 任务素材。
6. **独立迁移**：学习者在不照抄示例的情况下新增一个规则或错例类别，并证明它经过加载、执行、审核及评测后生效。

## 当前取舍

业务 Skill、知识沉淀、基础子图/流程组合、多模态评测、归因、自动优化和数据挖掘均进入主线。复杂多 Agent、MCP、多种优化器复刻、服务部署、Prompt Cache 深度调优及完整分布式后训练按需求扩展。
